## 2. โครงสร้างเว็บไซต์ 10 หน้าหลักตามสถาปัตยกรรมสารสนเทศ (Information Architecture)

1. **หน้า 1: หน้าหลัก (Home)**
   - พื้นหลังวีดีโอและแคนวาสละอองแสงอาทิตย์เคลื่อนที่ได้ (Video & Ambient Leaf Canvas) พร้อมปุ่มเปิด/ปิด
   - Wordmark และอัตลักษณ์ SACRED CANOPY
   - แถบค้นหาด่วน (Quick Search) พร้อมคำแนะนำ
   - หมวดหมู่ยอดนิยม 8 พรรณไม้ (Prefix A ถึง H)
   - ไม้มงคลแนะนำ (Featured Plants) และพรรณไม้เพิ่มล่าสุด
   - แบนเนอร์นำทางสู่ Plant Quiz
   - บทความล่าสุด และข้อความเจตนารมณ์วิชาการ

2. **หน้า 2: ฐานข้อมูลไม้มงคล (Plant Database)**
   - ระบบค้นหาหลายมิติ: ชื่อไทย, ชื่อวิทยาศาสตร์, ชื่อสามัญ, วงศ์พืช, รหัสพรรณไม้, คำค้น
   - ตัวกรองละเอียด 6 มิติ: หมวดหมู่, คติความเชื่อ, แสงแดด, ปริมาณน้ำ, สภาพพื้นที่, การดูแล
   - ตัวกรองความปลอดภัยสำหรับสัตว์เลี้ยง (Pet-Friendly Non-Toxic Toggle)
   - สลับมุมมองตาราง (Grid) และรายการ (List)
   - ระบบจัดเรียง (ก-ฮ, ฮ-ก, รหัสพรรณ, วันที่บันทึก)

3. **หน้า 3: รายละเอียดไม้มงคล (Plant Detail Modal & View)**
   - แบ่งข้อมูลออกเป็น 5 หมวดย่อยอย่างชัดเจน:
     - **พฤกษศาสตร์**: สัณฐานวิทยา ใบ ลำต้น ดอก ผล และจุดเด่น
     - **ความหมายและความเชื่อ**: มรดกทางวัฒนธรรม ทิศมงคลตามตำราไทยโบราณ
     - **การปลูกและดูแล**: ดิน แสง น้ำ ปุ๋ย การขยายพันธุ์ การตัดแต่ง และโรคแมลง
     - **ความปลอดภัย**: พิษวิทยาต่อมนุษย์และสัตว์เลี้ยง (อ้างอิง ASPCA / กรมการแพทย์)
     - **แหล่งข้อมูลอ้างอิง**: รายชื่อเอกสาร หอพรรณไม้ และงานวิจัย
   - ปุ่มบันทึกรายการโปรด, แชร์ผ่าน Web Share API หรือคัดลอกลิงก์, พรรณไม้ที่เกี่ยวข้อง

4. **หน้า 4: หมวดหมู่ไม้มงคล 8 สายพรรณ (Plant Categories)**
   - ระบบรหัสมาตรฐาน:
     - ไม้ยืนต้น: Prefix **A** (A01, A02...)
     - ไม้พุ่ม: Prefix **B** (B01, B02...)
     - ไม้ล้มลุก: Prefix **C** (C01, C02...)
     - ไม้เลื้อย: Prefix **D** (D01, D02...)
     - ไม้คลุมดิน: Prefix **E** (E01, E02...)
     - ปาล์ม: Prefix **F** (F01, F02...)
     - ไม้อวบน้ำ: Prefix **G** (G01, G02...)
     - ไม้ไผ่: Prefix **H** (H01, H02...)
   - คำอธิบายสัณฐานวิทยาและจำนวนต้นในแต่ละหมวด

5. **หน้า 5: ความหมายและคติความเชื่อ (Plant Beliefs)**
   - 8 ด้านสิริมงคล: โชคลาภ, การงาน, ความรัก, บ้านและครอบครัว, สุขภาพ, สติปัญญา, ปกป้องคุ้มครอง, สิริมงคลทั่วไป
   - ตำราทิศมงคล 8 ทิศ
   - คำชี้แจงเชิงวิชาการแยกแยะระหว่างคติชนวิทยาและวิทยาศาสตร์

6. **หน้า 6: เกมค้นหาต้นไม้ที่เหมาะกับคุณ (Plant Quiz)**
   - แบบทดสอบ 6 ขั้นตอน พร้อมแถบความคืบหน้า (Progress bar)
   - อัลกอริทึมคำนวณคะแนนความเข้ากันได้ (Compatibility Score %) กับพรรณไม้จริงในฐานข้อมูล
   - ระบบเตือนความปลอดภัยหากมีสัตว์เลี้ยงหรือเด็กเล็ก

7. **หน้า 7: ไม้มงคลของฉัน (My Favorites)**
   - คลังพรรณไม้ที่บันทึกไว้สำหรับสมาชิก
   - ระบบค้นหาและตัวกรองเฉพาะในรายการโปรด
   - การซิงค์และแจ้งเตือนสำหรับผู้เยี่ยมชม (Guest sync CTA)

8. **หน้า 8: บทความและเกร็ดความรู้ (Articles & Knowledge)**
   - บทความวิชาการพฤกษศาสตร์ ประวัติศาสตร์ไม้ในวรรณคดี และคู่มือความปลอดภัย
   - คัดกรองตามหมวดหมู่และช่องค้นหา
   - หน้าต่างอ่านบทความฉบับเต็มพร้อมระยะเวลาอ่าน

9. **หน้า 9: ช่วยเหลือและ Q&A (Help Center)**
   - ระบบค้นหาคำถาม-คำตอบ
   - Accordion คำถามที่พบบ่อย (เข้าถึงได้ด้วยคีย์บอร์ด)
   - คู่มือสรุปขั้นตอนการใช้งาน 3 ขั้นตอน
   - ปุ่มเชื่อมโยงสู่หน้าติดต่อเรา

10. **หน้า 10: เกี่ยวกับเรา (About Us)**
    - ปรัชญา “ร่มโพธิ์ ร่มไทร” และเสาหลัก 3 ประการ (Botanical, Culture, Well-being)
    - นโยบายการตรวจสอบข้อมูลและแหล่งอ้างอิง
    - ทำเนียบคณะผู้จัดทำและที่ปรึกษาสารสนเทศ

11. **หน้าติดต่อเรา (Contact Us)**
    - ผัง 2 คอลัมน์บน Desktop รองรับ Mobile แบบ 1 คอลัมน์
    - แบบฟอร์มส่งข้อความพร้อมการตรวจสอบความถูกต้อง (Validation)
    - บันทึกลงฐานข้อมูลจริง แสดงสถานะ Loading และ Success

12. **ระบบผู้ดูแล (Admin Dashboard)**
    - KPI สถิติพรรณไม้ บทความ และข้อความติดต่อ
    - ฟอร์มเพิ่ม/แก้ไขพรรณไม้ 6 แท็บ พร้อมสร้างรหัสใหม่อัตโนมัติ (A05, B05...)
    - ถังขยะ (Trash) รองรับ Soft-Delete และ Restore
    - กล่องข้อความติดต่อพร้อมเปลี่ยนสถานะ (ใหม่, กำลังดำเนินการ, ตอบกลับ, ปิดเรื่อง)
    - ปุ่ม Export Backup เป็นไฟล์ JSON

## 3. องค์ประกอบพิเศษตามข้อกำหนด (Special Interactive Features)

- **พื้นหลังวีดีโอเคลื่อนที่ได้ (Video & Ambient Botanical Background)**: แคนวาสจำลองแสงแดดส่องผ่านกิ่งก้านร่มโพธิ์ร่มไทร และใบไม้ลอยละล่อง พร้อมปุ่มสลับเล่น/หยุด
- **มาสคอตเว็บ "น้องต้นกล้า" (Nong Ton Kla)**: ตัวการ์ตูนต้นกล้าหลบอยู่มุมจอ กระพริบตา โบกมือ และมีกล่องข้อความแนะนำเกร็ดความรู้ประจำวัน สามารถกดคุยหรือนำทางไปทำแบบทดสอบได้
- **เคอร์เซอร์เมาส์ใบไม้สีเขียว (Leaf Cursor)**: ตัวชี้เมาส์รูปใบไม้มงคลสีเขียวขลิบทอง พร้อมประกายละอองแสงเมื่อเลื่อนเมาส์
- **ระบบบัญชีจริง**: ใช้ Firebase Authentication สำหรับอีเมล/รหัสผ่านและ Google Sign-in; ผู้สมัครใหม่เป็นสมาชิกทั่วไปเท่านั้น และสิทธิ์แอดมินต้องได้รับ Custom Claim จากผู้ดูแลที่เชื่อถือได้

## 4. โครงสร้างไฟล์และความปลอดภัย (Security & Deployment)

- `firestore.rules`: กำหนดสิทธิ์แบบ Role-Based Access Control โดยยืนยันแอดมินจาก Custom Claim เท่านั้น

- `firebase.json`: ตั้งค่า Firebase Hosting, Firestore Rules และ Cloud Functions; โปรเจกต์นี้ไม่ใช้ Firebase Storage

## 5. วิธีเปิดโปรเจกต์ใน Visual Studio Code และดูตัวอย่างเว็บไซต์

**โปรเจกต์นี้ใช้ React + TypeScript + Vite** (`src/main.tsx`) จึงไม่สามารถเปิดด้วยส่วนขยาย Live Server โดยตรงได้ เพราะ Live Server ให้บริการไฟล์ HTML แบบคงที่ แต่ไม่ได้แปลงไฟล์ `.tsx` และจัดการโมดูลของ Vite

ให้ใช้ Vite Development Server ซึ่งให้ผลใกล้เคียงกับการดูตัวอย่างผ่าน Live Server และรองรับการอัปเดตหน้าเว็บระหว่างแก้ไขโค้ด

### วิธีเปิดครั้งแรก (Windows)

1. แตกไฟล์ ZIP ไปยังโฟลเดอร์ที่ต้องการ เช่น `C:\Projects\sacred-canopy`
2. ติดตั้ง Node.js รุ่น LTS ที่รองรับ Vite รุ่นที่ใช้ในโปรเจกต์
3. เปิด Visual Studio Code
4. เลือก **File > Open Folder...** แล้วเลือกโฟลเดอร์ `sacred-canopy` ที่แตกไฟล์แล้ว (ต้องเลือกโฟลเดอร์ที่มี `package.json` อยู่โดยตรง)
5. เปิดเมนู **Terminal > New Terminal**
6. ตรวจสอบ Node.js และ npm:
   ```bash
   node -v
   npm -v
   ```
7. ติดตั้งแพ็กเกจ (ทำครั้งแรกหรือเมื่อมีการเปลี่ยน dependencies):
   ```bash
   npm install
   ```
8. เปิดเซิร์ฟเวอร์พัฒนา:
   ```bash
   npm run dev
   ```
9. รอจน Terminal แสดง URL เช่น `http://localhost:3000/`
10. กด `Ctrl` ค้างไว้แล้วคลิกลิงก์ใน Terminal หรือคัดลอก URL ไปเปิดใน Chrome/Edge

หยุดเซิร์ฟเวอร์ด้วย `Ctrl + C` ใน Terminal

### เปิดครั้งต่อไป

เปิดโฟลเดอร์เดิมใน VS Code แล้วรัน:
```bash
npm run dev
```

ไม่จำเป็นต้องติดตั้งแพ็กเกจซ้ำทุกครั้ง

### หากต้องการใช้ปุ่ม Run Task ใน VS Code

เปิดเมนู **Terminal > Run Task...** แล้วเลือก **SACRED CANOPY: Start Vite Dev Server** หากมีข้อความถามให้อนุญาต Task ให้ตรวจสอบว่าเป็นโปรเจกต์ที่ไว้ใจได้ก่อน

### ถ้าหน้าเว็บไม่เปิด

- ตรวจว่าเปิดโฟลเดอร์ที่มี `package.json` ไม่ใช่เปิด ZIP โดยตรง
- ตรวจว่าคำสั่ง `npm install` จบโดยไม่มี Error
- ตรวจ Terminal ว่า Vite แสดง URL และไม่มีข้อความ Error
- ถ้าแจ้งว่า `node` หรือ `npm` ไม่รู้จัก ให้ติดตั้ง Node.js แล้วปิด/เปิด VS Code ใหม่
- ถ้าพอร์ต 3000 ถูกใช้งานอยู่ ให้ปิดโปรเซสเดิม หรือแก้พอร์ตใน `vite.config.ts`/คำสั่ง dev ให้เหมาะสม
- เปิด DevTools ด้วย `F12` แล้วดูแท็บ Console หากยังพบหน้าว่าง
- หากการทำงานต้องใช้ Firebase ให้ตั้งค่าไฟล์ `.env` ตาม `.env.example` และคำแนะนำในหัวข้อ Firebase ด้านล่างก่อนทดสอบฟังก์ชันที่เชื่อมต่อบริการจริง

### ทำไมไม่ควรใช้ Live Server กับโปรเจกต์นี้

อย่าคลิกขวา `index.html` แล้วเลือก **Open with Live Server** สำหรับโปรเจกต์นี้ เพราะ `index.html` เรียก `src/main.tsx` ซึ่งต้องให้ Vite แปลงและจัดการโมดูล การเปิดด้วย Live Server อาจทำให้หน้าเว็บว่างหรือเกิดข้อผิดพลาดจากการโหลดโมดูล

## 6. การนำเข้าไฟล์ต้นไม้โดยเลือกหมวดหมู่

ใน Admin Dashboard ให้เปิด **ศูนย์นำเข้าไฟล์ (File Import Center)** แล้วทำตามนี้:

1. เลือกหมวดต้นไม้ในช่อง **หมวดหมู่ต้นไม้สำหรับไฟล์นี้** ได้แก่ A ไม้ยืนต้น, B ไม้พุ่ม, C ไม้ล้มลุก, D ไม้เลื้อย, E ไม้คลุมดิน, F ปาล์ม, G ไม้อวบน้ำ หรือ H ไม้ไผ่
2. เปิด **บังคับใช้หมวดที่เลือกกับทุกแถว** หากต้องการให้ข้อมูลทั้งหมดในไฟล์ถูกจัดเข้าหมวดเดียวกัน
3. เลือกไฟล์ `.csv` หรือ `.json` เพื่อนำเข้า
4. เมื่อเปิดการบังคับหมวด ระบบจะใช้ Prefix ของหมวดที่เลือกในการสร้างรหัสใหม่ และจะสร้างรหัสใหม่หากรหัสที่ติดมากับไฟล์ไม่ตรง Prefix
5. หากปิดการบังคับหมวด ระบบจะใช้หมวดที่ระบุในไฟล์เป็นหลัก (ถ้าไฟล์ไม่มีหมวด ระบบจะใช้หมวดที่เลือกเป็นค่าเริ่มต้น)

**ข้อควรระวัง:** สำรองข้อมูลก่อนนำเข้าไฟล์จำนวนมาก ไฟล์ที่มี `plantId` ซ้ำกับข้อมูลเดิมอาจเป็นการอัปเดต/แทนที่รายการเดิมตามกติกาของระบบ



## แก้ปัญหา npm dependency conflict (Windows/VS Code)

หากเคยติดตั้งแพ็กเกจจาก ZIP รุ่นก่อน ให้เปิด Terminal ในโฟลเดอร์ที่มี package.json แล้วรัน `npm install` ใหม่ โดยรุ่นนี้กำหนด Vite และปลั๊กอินให้ใช้สายเวอร์ชันที่เข้ากันได้มากขึ้น และไม่ต้องใช้ `--force` หรือ `--legacy-peer-deps` เป็นขั้นตอนแรก จากนั้นรัน `npm run dev` เพื่อเปิดตัวอย่างเว็บ
